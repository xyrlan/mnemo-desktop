The Nexus becomes the app, wave 1: eight pieces. Everything a person did in the workbench is
brought into the ship, so wave 2 can delete the workbench's interface in one pass with no function
lost.

**Read `docs/superpowers/specs/2026-10-15-nexus-app-design.md` first.** It holds every decision
(Q1–Q9) and where each workbench function goes. Where this contract and the spec disagree, ask the
parent session.

**Every seam is already on `main`**, so each piece compiles and tests alone and the eight merge in
any order. Nobody writes a stand-in for another piece's signature.
- **The ship's frame, `src/nexus/ui/`:**
  - `ui.css`: the `.nx` tokens and classes (`.nx-btn` with `data-tone`, `.nx-input`, `.nx-row`, …).
  - `windows.ts`: `registerWindow({ id, title, group?, order?, width?, render(params, close) })`,
    `openWindow(id, params)`, `closeWindow()`. `WindowHost` (`Window.tsx`) draws the open one in
    the ship's frame: Esc and the backdrop close it. `group: 'systems'` lists a window in the
    SYSTEMS menu, by `order`.
  - `menus.ts`: `registerMenu((target, ship, ctx) => MenuItem[])`. `ctx.open(id)` opens a figure's
    drawer tab, as a click does. `Menu.tsx` draws a menu.
  - `confirm.tsx`: `confirm({ title, body?, confirm, danger? }): Promise<boolean>`, drawn above any
    window. Every question that ends or publishes something asks it.
- **Right-click and the bar:** `ShipScene` calls `onMenu` with a robot, a captain, a deck or a dock
  (`data-ship-id`, `data-deck`, `data-dock`). The bar has PROJECTS (`openWindow('projects')`),
  MISSIONS (`openWindow('missions')`) and SYSTEMS ▾. `NexusView` draws the menu and the windows.
- **Registration:** `src/nexus/view.tsx` imports, eagerly, every `src/nexus/windows/*/index.ts(x)`
  and `src/nexus/menus/index.ts`. A piece registers there at import; nothing else wires it.
- **Sessions:** `src/nexus/drawer/open.ts` holds `SessionSpec` and the stubs `openSession`,
  `paneOf` and `endSession`.
- **The account switcher in the bar:** `src/nexus/accounts/ShipAccounts.tsx`, which the scene draws.

**Window params**, what each opener passes and each window reads:

| id | params |
|---|---|
| `projects` | `{}` |
| `missions` | `{ root?: string }`: a repo to open on |
| `changes` | `{ robotId: string; worktree: string; label: string }`: `worktree` is the robot's `child.cwd` |
| `memory`, `learned`, `setup`, `accounts`, `settings` | `{}` |

**What no piece edits:**
- the seams: `src/nexus/ui/`, `src/nexus/ship-types.ts`, `src/nexus/NexusView.tsx`,
  `src/nexus/view.tsx`, `src/nexus/ShipScene.tsx`, `src/nexus/ship-scene/`, `src/nexus/ship.ts`,
  `src/nexus/log.ts`. The `sessions` piece fills `drawer/open.ts`'s bodies, never its signatures.
- `src-tauri/`, `package.json`, `src/App.tsx`.
- `src/settings/`, `src/accounts/`, `src/vault/`, `src/learned/`, `src/setup/`, `src/home/`,
  `src/tasks/`, `src/github/`, `src/mission/`, `src/cockpit/`.

Importing what those export is expected; editing them is not. No piece adds a dependency.

**The look.** Every window, menu and question is the ship's, built from `src/nexus/ui/`: never
`@/ui`'s components, tailwind's workbench classes or the app's light theme. A window reads the
stores, clients and pure functions it needs. **Wave 2 deletes every workbench component**, so a
piece that imports a `.tsx` from outside `src/nexus/` lists it in its PR body, and wave 2 keeps
exactly those.

**Not in this wave:**
- **Deleting the workbench's interface.** Wave 2, one pass, after all eight merge.
- **Bringing the octopus into the ship.** A later round.

**English only:** every string a user can see.

The repo is **public**. Fixtures are synthetic: no real transcript or log row, no real session id,
and no repo or project name that is not this one or `mnemo`.

**Suite:** `pnpm test && pnpm build && pnpm --dir tools/preview test`, run with the
`DEVELOPER_DIR`/`PATH` prefix `CLAUDE.md` gives. CI runs on Windows too: compare paths as paths. The
whole app only works once all eight are merged; the parent checks it on screen at landing.

## sessions

- **files:** src/nexus/drawer/, src/nexus/store.ts, src/nexus/store.test.ts, src/nexus/command/, src/session/, src/terminal/view.tsx, src/layout/store.ts, src/layout/store.test.ts
- **exposes:** `openSession(spec: SessionSpec): Promise<void>`, `paneOf(sessionId: string): PaneId | null`, `endSession(pane: PaneId): Promise<void>`
- **consumes:** nothing
- **model:** opus
- **effort:** high

A session the Nexus starts, the drawer showing terminals only, and `/new`.

- **`openSession`:**
  - `claude` in `root`, as the workbench's *Launch agent* types it (its permission setting
    included); with `resume`, `claude --resume <id>`. `shell`: a plain shell in `root`. `command`:
    the saved command, typed once the prompt is up.
  - It runs in a pane with no view on screen. The layout store stays the app's session registry:
    the pane survives a restart through the daemon like any other, and the workbench is never
    shown or switched.
  - It opens in a drawer tab showing its live terminal, named for what it runs, the Nexus staying
    open. A started `claude` session's captain is the same figure as its tab.
- **`paneOf`:** the pane the app runs Claude session `sessionId` in, else null.
- **`endSession`:** the pane closes and its terminal ends; its drawer tab goes.
- **Drawer tabs come back after a restart**, each on its session, while its session is still held.
- **Terminal only** (spec, "The drawer shows terminals only"): the drawer's conversation face goes,
  with its switch, its state in the store, the ⌘⇧C claim and every test of them. A view drawn as a
  presentation (`present`) is the terminal, never the conversation face. The workbench's own panes
  keep what they draw until wave 2.
- **`/new <repo>`:** the bridge's prompt starts `claude` in that repo, a repo named as `/dispatch`
  names one. The hint lists it.
- **The drawer's Changes:** a robot's tab opens the full diff with
  `openWindow('changes', { robotId, worktree, label })`.

## menus

- **files:** src/nexus/menus/
- **exposes:** `shipMenu(target: MenuTarget, ship: Ship, ctx: MenuContext): MenuItem[]`
- **consumes:** `openSession(spec: SessionSpec): Promise<void>` from sessions, `paneOf(sessionId: string): PaneId | null` from sessions, `endSession(pane: PaneId): Promise<void>` from sessions, `ChangesWindow(props: ChangesWindowProps): JSX.Element` from changes
- **model:** opus
- **effort:** high

The right-click menus (spec Q2), registered from `src/nexus/menus/index.ts`. `ctx.open` opens a
figure.

- **A captain:**
  - **Open.**
  - **Close:** ends the session through `endSession` when `paneOf` finds it, after `confirm`. A
    session running outside the app has the item disabled, and its hint says it runs outside the
    app.
  - **Resume:** for one whose session ended, `openSession({ kind: 'claude', root, resume })`.
  - **Copy id.**
  - The empty chair (an orphan) offers what applies to it.
- **A robot:**
  - **Open.**
  - **Stop** and **Merge PR**, through `runAction` (`src/nexus/command/actions.ts`); a merge is
    confirmed first.
  - **Open PR:** the system browser.
  - **Changes:** `openWindow('changes', { robotId, worktree, label })`.
  - **Copy id.**
- **A deck or a dock:** **New session**, **Terminal here**, and the repo's saved commands
  (`settings.quickCommands[root]`), each through `openSession`.
- What does not apply to a figure's state is absent or disabled with a hint, never a click that
  fails.

## projects

- **files:** src/nexus/windows/projects/
- **exposes:** `ProjectsWindow(props: { close: () => void }): JSX.Element`
- **consumes:** `openSession(spec: SessionSpec): Promise<void>` from sessions
- **model:** opus
- **effort:** high

The PROJECTS window (spec Q3, Q4): every repo the app knows, whether or not a session is live in it.

- A row per repo: its name and path, the sessions live in it, **New session**, **Terminal**, and its
  saved commands, run with one click.
- Saved commands are added and removed here (`settings.quickCommands`).
- The window: **Add** (an existing folder), **Clone** (a git URL, into the clone base), **Open
  folder**, as the workbench's new-workspace flows do them today.

## changes

- **files:** src/nexus/windows/changes/, src/diff/
- **exposes:** `ChangesWindow(props: ChangesWindowProps): JSX.Element`
- **consumes:** nothing
- **model:** opus
- **effort:** high

`ChangesWindowProps` is `{ robotId: string; worktree: string; label: string; close: () => void }`.

The Changes window (spec Q7): the full diff of a child's worktree against its base, and the notes
for the agent written on its lines (`src/diff/`), sent the way the diff pane sends them today.

- In the ship's look, wide enough to read a diff.
- A worktree that is gone, or has no change, says so.
- `src/diff/` is this piece's to change, so the window and the notes work outside the workbench. The
  workbench's diff pane keeps working until wave 2.
