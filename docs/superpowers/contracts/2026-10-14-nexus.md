The Nexus round, five pieces. The fleet becomes a drawer that draws a small sci-fi world:
- one territory per repo, holding its archive (the project's vault);
- one nexus per live session that is not a dispatched child;
- one robot per child, in a ring around its nexus;
- packets for mnemo's memory events, travelling between archives and agents.

**Read `docs/superpowers/specs/2026-10-14-nexus-design.md` first.** It holds every decision
(Q1–Q26), the signal tables (Q18, Q22) and the facts behind them. Where this contract and the spec
disagree, ask the parent session.

**Every seam is already on `main`**, so each piece compiles and tests alone, and the five merge in
any order. Nobody writes a stand-in for another piece's signature, in the worktree or the PR.

- `src/nexus/types.ts` — every shared type (`World`, `Territory`, `Nexus`, `Robot`, `Archive`,
  `ArchiveCounts`, `Packet`, `SpriteManifest`, `Target`, the pose/badge/halo unions,
  `ACCESSORIES`). **No piece edits it.** A type that does not fit is a question for the parent,
  not an edit.
- `src/mission/types.ts` — `ChildSession.notice?: 'held' | 'delivered' | null`, typed and not yet
  filled.
- `src/nexus/NexusDrawer.tsx`, `view.tsx`, `store.ts`, `client.ts` — the drawer, its wiring
  (snapshot, pulse log, archives poll, reduced motion, visibility, usage start, pick → action →
  close), `nexus.toggle` and the sidebar entry. No piece edits them.
- Stubs with final signatures: `world.ts`, `packets.ts`, `actions.ts`, `usage.ts`, `HoverCard.tsx`,
  `Scene.tsx` (its props are final).
- `src-tauri/src/nexus.rs` — `nexus_archives` with a stub body, **registered in `lib.rs`**;
  `ArchiveCounts` serialises as `types.ts` reads it (test on main).

**No piece edits `src-tauri/src/lib.rs`, `Cargo.toml`, `package.json`, `src/App.tsx`,
`src/layout/`, `src/actions/`, `src/sidebar/` or `src/nexus/types.ts`.** None adds a dependency.

The repo is **public**. Fixtures are synthetic: no real transcript or log row, no real session id,
and no repo or project name that is not this one or `mnemo`.

Suite: `pnpm test && pnpm build`, run with the `DEVELOPER_DIR`/`PATH` prefix `CLAUDE.md` gives.
A Rust piece also runs
`CARGO_TARGET_DIR=$HOME/.cache/mnemo-desktop-nexus-<piece> cargo test --manifest-path src-tauri/Cargo.toml`;
that target is temporary and is pruned at landing. CI runs on Windows too: compare paths as paths.
The whole view only works once all five pieces are merged; the parent checks it on screen at landing.

## world

- **files:** src/nexus/world.ts, src/nexus/world.test.ts
- **exposes:** `buildWorld(snap: Snapshot, archives: ArchiveCounts, now: number): World`
- **consumes:** nothing
- **model:** opus
- **effort:** high

The snapshot as a world. It is pure, and the same inputs give the same world.

- **Territories (Q5).** One per repo root, from the snapshot's repo groups; `<repo>-wt-*`
  worktrees fold into their repo. Each territory has its archive, built from the counts with a
  `Tier`, and the world has the universal core.
- **Nexuses (Q25).** One per live session that is not a dispatched child, with or without
  children. A parent no longer alive whose children are is a `dead` nexus with `parent: null`. A
  child whose parent is unknown still appears, under a dead nexus of its own repo, and is never
  dropped.
- **Robots.**
  - Class comes from the model (Q13), level from the effort (Q3).
  - The accessory is seeded from the id: deterministic, and in `[0, ACCESSORIES)`.
  - The label is `#<issue>` from the worktree, else the contract piece, else the short id.
  - The tool comes from the timeline's `Running …` detail.
- **Pose, halo, badge and exit** follow the spec's Q18 table exactly. Exits follow Q12: `merged`
  for a merged PR; `powered-down` for a stop without a PR once `notice` is `delivered`. A robot
  whose exit has played long enough leaves the world. Decide how long, and test it.
- `notice` is absent until the `notice` piece lands. Absent means unknown, never `delivered`.

## memory

- **files:** src/nexus/packets.ts, src/nexus/packets.test.ts, src-tauri/src/nexus.rs
- **exposes:** `packetsFrom(events: PulseEvent[], world: World, now: number): Packet[]`, `injectedRules(events: PulseEvent[], sessionId: string): string[]`, `nexus_archives() -> ArchiveCounts`
- **consumes:** nothing
- **model:** opus
- **effort:** medium

mnemo's memory made visible: the spec's Q22 table, with Q23's coalescing.

- **Attribution.** A packet goes to a robot or a nexus by `session_id`. An `enrich` packet goes by
  which worktree holds the event's file. An event no agent can be named for is a `flash` on its
  territory's archive.
- **Coalescing.** Events for one agent within ~5 s become one packet with `count`.
- **Packet ids** are stable across calls, so the scene plays each packet once.
- **`injectedRules`** gives the slugs mnemo put in front of one session, for the hover card.
- **`nexus_archives`** counts live pages per project and the universal ones from the vault, with no
  `mnemo` subprocess. The pulse's project names must match the keys. Noise is left out, as
  `vault_level` already leaves it out; read `src-tauri/src/vault.rs` before counting anything
  yourself.

## notice

- **files:** src-tauri/src/mission.rs
- **exposes:** `ChildSession.notice: Option<String>` serialised as `"held" | "delivered" | null`
- **consumes:** nothing
- **model:** opus
- **effort:** medium

Fills `notice` on every child in the snapshot (spec Q12):
- `held` while its finish notice waits for the parent's next prompt;
- `delivered` once the parent has it;
- null while it has sent none.

mnemo writes these records in the vault's `.mnemo/`: `held-notices.jsonl` and
`session-inbox.jsonl`, with `child-reports.jsonl` alongside. Read the writers in the mnemo repo
(`core/sessions/held_notices.py`, `core/sessions/inbox.py`) before parsing anything. The field is
`#[serde(default)]`, so an old snapshot still reads.

## scene

- **files:** src/nexus/Scene.tsx, src/nexus/scene/, src/nexus/nexus.css, src/nexus/sprites/, src/nexus/sprites.ts
- **exposes:** `Scene(props: SceneProps): JSX.Element`, `SPRITES: SpriteManifest`
- **consumes:** `HoverCard(props: HoverCardProps): JSX.Element` from interact
- **model:** opus
- **effort:** high

The world drawn.
- **Layout (Q17).** Territories in a grid that fits the drawer, with no camera; robots in a ring
  around their nexus, holding up to 15 per nexus; the archive in each territory and the universal
  core in the middle.
- **Sprites (Q4, Q16).** DOM sprites from `SPRITES`, at an integer scale with
  `image-rendering: pixelated`.
- **State (Q11, Q18).** Halos are the four `--state-*` tokens. Badges (`alert`, `zzz`, the flags,
  `fire`) and the `×N` counter are drawn in code.
- **Motion.**
  - Arrival warps in from the nexus.
  - Exits play `merged` or `powered-down`.
  - Packets travel along their `path`, each played once by `id`.
- **Reduced motion.** No travel and no loops: halos, badges and counters only.
- **Hidden window.** All animation pauses.
- **Clicks and hovers.** A click calls `onPick`; a hover shows `HoverCard`.

The **placeholder** sprite set is this piece's to make: simple, legible pixel shapes per class,
pose, nexus pose, tier, core and packet, at the spec's sizes, as files under `src/nexus/sprites/`,
described by `SPRITES`. The final art replaces those files and values later, never the shape.

## interact

- **files:** src/nexus/actions.ts, src/nexus/actions.test.ts, src/nexus/HoverCard.tsx, src/nexus/HoverCard.test.tsx, src/nexus/usage.ts, src/nexus/usage.test.ts
- **exposes:** `openNexus(nexus: Nexus): void`, `openRobot(robot: Robot): void`, `openArchive(root: string, archive: Archive): void`, `HoverCard(props: HoverCardProps): JSX.Element`, `startNexusUsage(log: (row: Record<string, unknown>) => void, now: () => number): () => void`
- **consumes:** `injectedRules(events: PulseEvent[], sessionId: string): string[]` from memory
- **model:** opus
- **effort:** medium

Everything the view does when touched (spec Q15, Q26).
- **`openNexus`** reveals the session's terminal the way a kanban card does (`revealCard`). For a
  `dead` nexus it offers `claude --resume` in a new terminal, on the session's account. For a
  session alive outside the app, it says so and opens nothing: never a second copy of a live
  session.
- **`openRobot`** `claude attach`es the child, on its account (`attachChild`).
- **`openArchive`** opens that project's Memory panel.
- **`HoverCard`**:
  - for a robot: label and title, model and effort, state, current tool, age, PR and checks,
    context tokens, and the rules mnemo injected;
  - for a nexus: its session and its robots;
  - for an archive: its pages.
- **`startNexusUsage`** logs `{event: 'nexus.open'}` once. It then logs
  `{event: 'nexus.visible', ms}` for the time on screen with the window focused, at least every
  `BEAT_MS` and once more at stop. mnemo's measure tool reads these rows, so their names are fixed.
